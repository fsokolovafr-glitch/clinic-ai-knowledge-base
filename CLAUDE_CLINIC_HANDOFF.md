# Передача Clinic AI в новый Claude клиники

## 1. Цель проекта

Этот репозиторий содержит внутреннюю базу знаний косметологической клиники. Задача Claude — помогать косметологу разбирать результаты диагностики M17 и подбирать возможные варианты профессионального и домашнего ухода на основании проверенных источников.

Claude не ставит окончательный диагноз, не заменяет врача и не принимает клинические решения самостоятельно.

## 2. Репозиторий

Репозиторий GitHub:

https://github.com/fsokolovafr-glitch/clinic-ai-knowledge-base

На момент передачи репозиторий приватный. Новый Claude должен получить доступ через подключённый аккаунт GitHub клиники, GitHub Connector или подключённую локальную папку. Сообщение в чате «даю полный доступ» само по себе технический доступ не создаёт.

## 3. Что находится в репозитории

Корневые файлы:

- `README.md` — краткое описание базы;
- `CLAUDE_CONTEXT.md` — правила работы с базой;
- `MASTER_KNOWLEDGE_BASE.md` — основной промежуточный справочник;
- `SOURCE_INDEX.json` — реестр источников, страниц и контрольных сумм;
- `MARGOLINA_PARTS_README.md` — инструкция по частям больших томов;
- `S11_INTAKE_NOTE.md`, `S12_INTAKE_NOTE.md`, `S13_INTAKE_NOTE.md` — заметки о добавленных учебниках.

В папке `sources/` находятся исходные материалы:

- M17 Brochure и M17 User Manual;
- HydroPeptide Training Guide и Men's Facial;
- GenX Technical Dossier и Professional Catalogue;
- md:complex / md:peel GenX Catalogue;
- Бочарова, «Основы практической косметологии»;
- Марголина, «Новая косметология», том 1;
- Марголина, «Новая косметология», том 2;
- первоначальный Project Brief.

Тома Марголиной сохранены в GitHub частями из-за ограничения размера одного файла. Это не разные книги. Части нужно рассматривать в порядке, указанном в `MARGOLINA_PARTS_README.md`.

## 4. Что нужно сделать при первом запуске

1. Проверить, что открыт именно репозиторий `clinic-ai-knowledge-base`.
2. Прочитать `README.md`.
3. Прочитать `CLAUDE_CONTEXT.md`.
4. Прочитать `MASTER_KNOWLEDGE_BASE.md`.
5. Прочитать `SOURCE_INDEX.json`.
6. Прочитать `MARGOLINA_PARTS_README.md`.
7. Проверить, что папка `sources/` доступна.
8. Составить короткий отчёт: какие файлы доступны, какие источники зарегистрированы, какие источники ещё имеют статус `pending_structured_review`.
9. Не анализировать все книги целиком без отдельной команды.

## 5. Экономия токенов

Не загружать все PDF одновременно.

Рабочий порядок:

1. Сначала использовать `MASTER_KNOWLEDGE_BASE.md`.
2. Затем обратиться только к нужному источнику.
3. Затем открыть только нужные страницы.
4. Большие книги Марголиной и Бочаровой анализировать тематическими блоками, а не целиком за один запрос.
5. После отдельного тематического разбора добавлять подтверждённые сведения в master-файл только после проверки источника.

Хранение файлов в GitHub само по себе токены не расходует. Токены расходуются только во время чтения и анализа текста.

## 6. Рабочий алгоритм для M17

Когда загружен результат M17:

1. Определить, что именно прислано: фото лица, скриншот показателей или полный отчёт.
2. Перечислить показатели M17 без интерпретации.
3. Отдельно указать возможные состояния кожи и степень уверенности.
4. Сопоставить состояния с информацией из `MASTER_KNOWLEDGE_BASE.md`.
5. При необходимости проверить конкретные страницы исходных PDF.
6. Предложить допустимые варианты профессионального протокола только по данным источников.
7. Предложить варианты домашнего ухода только по зарегистрированным продуктам и инструкциям.
8. Отдельно указать, каких данных не хватает.
9. Для каждого важного вывода дать ссылку вида `S03, PDF page 53`.
10. Завершить напоминанием, что решение проверяет косметолог клиники.

Фотография лица сама по себе не является результатом M17. Если показателей прибора нет, нужно прямо написать, что полноценная интерпретация M17 невозможна.

## 7. Правила точности и безопасности

- Не придумывать противопоказания, дозировки, параметры, пути введения и интервалы.
- Не превращать рекламные claims производителя в доказанный клинический факт.
- Разделять: инструкция производителя, claim производителя, данные M17 и интерпретация Claude.
- Если сведения отсутствуют, писать: «в источнике не указано».
- Не ставить окончательный диагноз.
- Не назначать медицинское лечение.
- Не рекомендовать процедуру без проверки специалистом клиники.
- Не использовать персональные данные пациента без необходимости.
- Для тестов использовать обезличенные результаты M17.

## 8. Первый тестовый запрос

После подключения репозитория можно отправить:

«Проверь доступ к базе знаний клиники. Прочитай README.md, CLAUDE_CONTEXT.md, MASTER_KNOWLEDGE_BASE.md, SOURCE_INDEX.json и MARGOLINA_PARTS_README.md. Не анализируй PDF целиком. Сообщи, какие источники доступны, какие имеют статус pending_structured_review и готов ли ты работать по правилам базы.»

Для первого теста M17:

«Проанализируй этот обезличенный результат M17 по базе клиники. Сначала перечисли показатели прибора, затем возможные состояния кожи, затем варианты профессионального протокола и домашнего ухода. Для каждого вывода укажи источник и страницу. Не ставь окончательный диагноз. Если данных недостаточно, напиши, чего именно не хватает.»

## 9. Что ещё не завершено

База является промежуточной. В `MASTER_KNOWLEDGE_BASE.md` уже разобраны основные источники M17, HydroPeptide, GenX и md:complex/md:peel. Учебники Бочаровой и Марголиной зарегистрированы и сохранены, но ещё не разобраны полностью в master-файл. Их следует обрабатывать постепенно по темам.

Также перед клиническим использованием нужно проверить актуальные инструкции конкретных продуктов, действующие протоколы клиники, доступные процедуры, противопоказания и версию программного обеспечения M17.

## 10. Перенос на аккаунт клиники

Когда будет создан GitHub аккаунт клиники:

1. Клиника должна сообщить точное имя GitHub аккаунта.
2. Владелец текущего репозитория инициирует Transfer ownership.
3. Аккаунт клиники принимает перенос.
4. После переноса новый Claude подключает уже адрес репозитория клиники.
5. Проверяется доступ к корневым файлам и папке `sources/`.
6. Проверяется, что репозиторий остаётся приватным.

Для передачи Claude-проекта на рабочее пространство клиники нужен аккаунт или организация Claude клиники. До этого рабочие инструкции и основные файлы можно использовать в текущем проекте Claude.
